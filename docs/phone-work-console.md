# 手机蓝牙 App 工作台

手机选择 App 后显示该 App 的快捷操作。Mac 管理配置，手机执行及排列按钮；没有独立工作模式。**当前控制通道使用蓝牙 BLE，已移除 IP 输入和局域网控制代码。**

## 当前仿真版本

按用户要求先仿真、再真机。首轮仿真已完成；随后普通蓝牙版已安装到 realme RMX3888，完成真机启动及未配对页面检查。Mac 真实蓝牙服务已成功发布，等待扫码及两端确认。实际无线指令与系统按键执行仍待完成配对和辅助功能授权后验证，见[真机交接记录](validation/phone-work-console-device-handoff.md)。

界面仿真必须显式用 Debug 参数构建：

```sh
cd mobile
flutter build apk --debug --dart-define=REPOSE_CONSOLE_SIMULATION=true
```

本次保留安装包 `mobile/build/app/outputs/flutter-apk/app-console-simulation.apk`。打开 **App 快捷操作 → 模拟 Mac · 蓝牙仿真**，体验切换 App、两秒按键序列、中途停止和按钮拖动。页面显著标记仿真；此界面使用模拟 Mac，不触发真实系统按键。普通构建不启用仿真。

协议仿真另行运行生产 Kotlin 加密/分片代码与生产 Rust 工作台服务，通过进程管道模拟传输，并使用假键盘记录结果。它验证加密、顺序、配置同步、执行间隔、取消、断连、重放与撤销，不以真实 BLE 无线验证冒充仿真通过。

## 真机阶段的使用流程

1. Mac 与 Android 均使用本分支的普通 Debug 构建，打开两端蓝牙。
2. 在既有 **手机钥匙** 流程完成 Android 系统关联、扫描 Mac 配对二维码及两端确认。无需第二个工作台二维码。当前 Debug 配对凭据只保存在进程内，重启后需重新配对。
3. Mac 进入 **App 工作台**，开启蓝牙控制，并在系统设置 → 隐私与安全性 → 辅助功能中允许 Repose。
4. 手机工作台选择已配对的 Mac 连接，点击 tmux、Codex 或飞书，执行对应按钮。
5. tmux 需已在目标终端运行，默认目标 Terminal、前缀 Ctrl+B；可在 Mac 将目标改为 iTerm 的 `com.googlecode.iterm2` 或调整前缀。关闭分屏预置打开 tmux 自身确认提示，不自动确认。

Mac 可编辑 App、按钮名称/图标、组合键，录制或手动添加多个步骤。例如 **⌘K → 等待 2 秒 → Enter → 等待 1 秒 → ⌘V**。每段等待以秒配置，支持调整顺序、删除和追加，保存后同步到手机。先保存再试运行。

手机进入 **调整位置**，长按拖动任意按钮（包括序列按钮）或使用移动箭头，再保存。每个 App 顺序独立保存，编辑布局时不执行按钮。

录制范围仅为 Mac 工作台录制区，Escape、焦点离开或页面隐藏结束录制。系统拦截的按键可手工填写，不录制输入法合成文本。按键依据 Mac 当前键盘布局解析。

## 连接和取消规则

- 使用现有配对二维码中的密钥授权 BLE 控制，仅 Mac 确认配对后可执行。密钥不传给 Flutter、不经明文 BLE 发送；撤销配对立即失效。
- 每次订阅生成新 challenge，AES-256-GCM 加密消息、HKDF 派生连接密钥，每方向递增计数防重放。
- 一个控制连接、一条在途请求；分片严格顺序，通知遵守 MTU 与背压。不重试执行请求。
- 手机后台心跳不禁用操作按钮；点击会在当前心跳完成后发送一次，期间断连则丢弃。不会并发调用 GATT。
- Mac 区分蓝牙关闭、未授权、不支持、服务发布中和发布失败；服务已发布且广播成功后才显示等待配对或连接。
- 每步发键前检查目标 App、取消、锁屏/休眠、强制休息和连接代次。取消或断开后不补发剩余按键。心跳超过 3 秒停止，已发按键无法撤回。
- Mac 是配置来源；手机只调用已保存操作 ID 或调整布局。版本号防止手机排序覆盖 Mac 新编辑。
- 每 App 最多 12 按钮，每序列 20 步、每步等待 0–5 秒，最多 16 App，配置上限 192KiB。未变化配置通过 knownRevision 省略，减少蓝牙传输量。
- 保持原有 Debug/Profile/Release 配对门控；当前普通蓝牙实现可供后续 Android Debug 真机验证，未宣称已通过无线验收或 iOS 验收。
