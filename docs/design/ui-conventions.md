# 界面约定

每一条都来自这个项目真实出过的问题，后面都附着那次的现场。没有出过问题的
"最佳实践"不写在这里——一条没有伤疤的规则，下一个人没有理由遵守它。

改界面之前读一遍。加规则的时候，附上让你想加它的那次失败。

---

## 一、说真话

### 1.1 界面不能宣称代码没做的事

这一条被违反过至少八次，是这个项目最贵的一类 bug。现场：

- 「移除手机钥匙」输完管理员密码，**界面没有任何变化**——移除其实完整成功了，
  但返回值里没有 `state` 字段，面板不刷新。成功和失败长得一模一样。
- 手机主屏写着「守着你的 Mac」，而它读的是**开关**，不是**进程**。被系统杀掉
  之后照样这么显示。
- 「已配对」读的是芯片里有没有钥匙，不是**这一次配没配成**。失败之后它继续
  显示上一把旧钥匙的成功。
- Mac 点完确认立刻说「配对完成」，**它根本不知道手机那边点没点**。
- 面板对任何密钥都写「这是 USB 下发的开发密钥」——真配对上线后，这句话变成了
  **反方向的假话**。
- `keys_removed: true` 是代码里写死的字面量，而密钥还在盘上。

**做法**：界面上每一句关于系统状态的话，都要能指出它读的是哪一个可观测事实。
指不出来的，就不要说。

### 1.2 过了密码之后，把读回来的事实给你看

不是「已完成」，是重新去系统里读一遍，然后把读到的列出来：

```
已移除
✓ 锁屏规则已从备份还原
✓ 组件已删除
✓ 这台 Mac 上的配对密钥已删除
现在的锁屏规则：authenticate-session-owner-or-admin
```

用户刚刚交出了管理员权限，他有权看到那一下换来了什么。

### 1.3 做不到的事直说做不到

- 远程停用没做 → 就写「远程停用还没做，每台 Mac 要各关一次」，不写含糊的安慰。
- 「允许下一次解锁」不会替你按回车 → 写在**按钮旁边**，不是帮助页里。
  （后来这个按钮被删了，见 3.1。）

### 1.4 三态，而不是两态

「不知道」是正经答案，不是占位符。手机看不到 Mac 时，可能是不在附近、睡着了、
关机了、或者没开 App——**从两个真答案里挑一个来冒充"不知道"，两种挑法都会把人
送错地方**。

而且要说出它分不清哪几种情况，不要只写「未知」——那读起来像故障。

## 二、控件

### 2.1 一个状态，一个动作，而且那个动作一定能做成

刚装好、还没配对时，面板提供「锁屏，试一次」。**没有密钥，插件只会拒绝**——
这个按钮在这个状态下必定失败。而能修复这件事的「配对手机」按钮，它对应的状态
在代码里从来没被返回过，所以你永远看不到它。**用户被卡在一个界面上没有出路的
状态里。**

如果某个按钮在当前状态下必然失败，它就不该出现在这个状态里。

### 2.2 控件必须绑在它能改变的事实上

开关的 `enabled` 读的是 `state`，而 `state` 在监测跑与不跑时**都是
`awaiting-verification`**。于是开关永远显示"开"，只有关闭分支走得到，打开分支
永远走不到。**点多少次都不动。**

### 2.3 成功之后界面必须变化

手机上点「一样，完成配对」，toast 说配对完成，**屏幕一动不动**（窗口没关，又
渲染了一遍同样的数字和按钮）。自然反应是再点一次——而这一次报了失败，尽管第一次
就成功了。

**一个成功之后毫无变化的界面，就是在邀请你重复操作。**

### 2.4 长操作不能冻住界面，但也不能提前报成功

启动在场监测要等特权半边起来。早期版本立刻返回成功 → 面板读到还没写的状态文件
→ 开关保持灰 → 用户按第二次。改成等待之后，**同步的 Tauri 命令跑在主线程上，
整个窗口冻了 25 秒**。

两个都不行。正确做法：异步等待 + 界面显示进行中。

### 2.5 一个决定，一个控件

未安装时，「回车解锁」开关和「开始设置」按钮并排，点哪个都打开同一张说明书。
读的人得先停下来判断它们是不是一回事。

## 三、技术细节

### 3.1 默认折叠。折叠线上面只放会改变用户决定的事实

安装说明书曾经是一整屏密密麻麻的文字，语气像免责声明，**读完的感受是"别装"
而不是"我懂了"**。一屏读不完的知情说明等于没有说明——人只会往下滚找按钮。

现在折叠线上面只有三条：它动哪里、怎么还原、它挡不住什么。其余收进「更详细的」。

**收起来，不是删掉**：想看的人要在他想看的那一天看得到。

### 3.2 十六进制、路径、进程名、日志，一律进「技术细节」

配对流程曾经先让你比对六位数字，紧接着弹出一串八位十六进制「配对编号」，
**屏幕上没有任何东西说明该核对哪一个**。

现在设备名当主角（「已经和『Jingmin 的 MacBook』配对」），指纹进折叠区。
它还在，还能对，只是不再和那六位抢注意力。

### 3.3 屏幕上永远不同时出现两个编号

需要人核对的只有配对时那六位数字。**在一个防中间人的流程里，让人分不清该核对
哪个号码，正是攻击者需要的那种困惑。**

### 3.4 说后果，不说机制

| 不要 | 要 |
|---|---|
| 在场监测未运行 | 已关闭 · 现在只能用密码登录 |
| Mac 听得到这台手机时才有用 | Mac 在附近时才有用 |
| STALE：45 秒没有采样 | 没有看到你的手机 |

用户不需要在脑子里装着我们的机制。

## 四、弹窗

### 4.1 内边距

`.modal` 自己不设内边距，每种弹窗各自声明——于是漂成了 39px、35px、32px
三个值。手机钥匙那几个**一个都没声明**，字直接贴着边框。

```
桌面   30px 32px 32px     上边紧一点，因为关闭按钮已经占着那个角
窄屏   24px 22px 26px     760px 以下，同样的值会吃掉三分之一行宽
```

### 4.2 授权弹窗必须显示产品名

macOS 把授权弹窗归给**发起请求的可执行文件**。借道 `/usr/bin/osascript` 就写
"osascript"——**一个用户从没安装过的名字，出现在这个产品里唯一要他输入管理员
密码的时刻**。

「不要把密码给你不认识的软件」是个好习惯，而我们在把人训练成相反的样子。

要点之前先说会看到什么，而且那句话必须是真的。

### 4.3 一屏读得完

见 3.1。

## 五、语言

### 5.1 中文要像中文

写过「没有在等手机」。没人这么说话。

### 5.2 标题写功能名，状态写下面一行

有一版让标题在「正在等你的手机」和「没有在等手机」之间来回跳。中文 App 不这么
读——标题命名事物，开没开在下面。

但**一个永不变化的标签也没法告诉你控件有没有生效**（见 2.3），所以状态那一行
必须变。

### 5.3 非正常状态的第二句，永远先回答同一个问题

**我还进不进得去。**

出错时人最先想知道的不是哪里坏了。所以每一个异常状态先回答这个，再说原因，
然后给一个按钮。

### 5.4 错误提示要说清怎么办，最好带上去那里的按钮

写过「这台 Mac 的锁屏密码有延迟，把它设成『立即』」——**没说在哪里设**。
（而且那条提示本身是错的，见 6.2。）

现在写明「系统设置 → 锁定屏幕 → …」，并且配一个直接打开那个面板的按钮。

面板还出过一个「前往设置」，**指向用户已经站着的那一页**。

## 六、其它

### 6.1 没有红色

警示一律用暖琥珀（`#f7f0e9` / `#ecdfc8` / `#8a6f42`）。语义色和品牌绿分开。

### 6.2 一条带版本号的事实，版本变了就不再是事实

`open -a ScreenSaverEngine` 能锁屏——在 macOS 14.6.1 的 VM 上验证过，当时确实
是对的。这台日常机是 macOS 26，同一条命令**返回成功但屏幕纹丝不动**，于是桥
连打三行"正在启动屏保"而什么都没发生。

写下结论时带上验证环境；读到结论时看一眼那个环境还在不在。

### 6.3 只有真正有顺序的东西才编号

安装是一个序列（安装 → 配对 → 试一次），所以它带编号，而且是界面里唯一带编号
的地方。给不是序列的东西编号，是拿结构装饰内容。

手机上曾经有「安全检查 / 设备配对 / 距离校准」三步，**而距离校准根本没实现**。
一个人做不完的步骤，比没有步骤更糟。

### 6.4 空状态不是列表的缩小版

一个空盒子加一个「添加」按钮，回答不了站在那里的人真正的问题：这是什么、
它会对我的 Mac 做什么。

### 6.5 名字来自对方的，要说明它只是标签

配对时两端交换设备名。那个名字**不在 SAS 记录里**，是对方随便报的——所以它是
用来认的，不是用来核对的，界面上要写清这一点。

而且只在人确认数字一致之后才保存：**从一次被否决的会话里留下的名字，就是冒充
者的名字**。

## 七、可读性（实测，不是感觉）

这一节是 2026-09-11 对 `src/styles.css` 做的一次实测，不是照搬指南。

### 7.1 字号：一半以上的声明太小了

桌面样式里 `font-size` 的分布：

```
 6px   2
 7px   2
 8px  10
 9px  18
10px  31   ← 到这里为止 63 处，占全部声明的 52%
11px  21
12px  11
13px+ 其余
```

Apple 的 HIG 给 macOS 的建议是正文 13pt、最小 11pt。这一版有 63 处在 10px 及
以下，最小到 6px。

**约定**：新写的界面正文不低于 12px，辅助说明不低于 11px。低于 11px 只用于
纯装饰性的字符（比如已经有图标表意的角标），并且不承载任何必要信息。

存量的不一次性扫——那会把整个视觉比例打乱。**改到哪一块，顺手把那一块提上来。**

### 7.2 对比度：两处不达标

在 `#fbfcf9` 底上实测（正文需 4.5:1）：

| 用途 | 现在 | 比值 | |
|---|---|---|---|
| `--text` `#303b32` | | 11.35:1 | 通过 |
| `--subtle` `#677160` | | 4.96:1 | 通过 |
| `--green` `#526a43` | | 5.82:1 | 通过 |
| `--muted` `#8b9288` | | **3.11:1** | 只够大字，却用在 9–10px 上 |
| `.security-permission` `#8b9d7c` 在 sage 上 | | **2.59:1** | 不达标 |
| 琥珀警示 `#8a6f42` | | 4.19:1 | 擦边 |

`--muted` 是**双重失败**：又小又浅，而且它正是"次要说明"的默认色——所以
最需要人看清的解释性文字，恰好是最难读的那一档。

保持色相不变、只压明度，能过线的值：

```
--muted                  #8b9288  →  #6f766c   4.55:1
.security-permission     #8b9d7c  →  #627255   4.60:1
琥珀警示文字               #8a6f42  →  #83693f   4.58:1
```

这三个改动会影响整个 App 的观感，**没有动**，等一次专门的视觉评审。
这里先把数字记下来，免得下次还得重新量一遍。

### 7.3 怎么复量

```sh
# 字号分布
python3 -c "$(sed -n '/=== 正文字号分布/,\$p' docs/design/ui-conventions.md)"  # 见 git 历史里的脚本
```

比值公式是 WCAG 的相对亮度，不依赖任何库，几行就能写完——需要时重写比存一份
脚本更省事。
