# 手机怎么按到 Mac 的键

2026-09-12 · 设计稿，**还没实现**

Mac 侧已经能按了（`src-tauri/src/console.rs` + `native/work_console.m`，见
`3c590d4`）。差的是手机上那一排按钮。

## 一个不明显的问题：目录在哪一端

先说一个让人意外的结论：**发指令很便宜，发目录很贵。**

在场信标里已经有一个 `cmd` 字节，经过 K 认证、带单调序号防重放，而且**已经实测跑通
过**（`presence-verify: command 1 seq=20 accepted from keyId=1`，手机上的「锁定 Mac」
就是它）。再加 240 个 cmd 取值，让每个快捷操作占一个，不需要任何新协议、不需要在
手机上开一个可连接的 GATT 服务、不多一寸攻击面。

问题不在发指令，在于**手机不知道该显示什么按钮**。操作的名字、图标、属于哪个 App，
全都在 Mac 上的 `work-console-v1.json` 里。一个字节装不下「左右分屏 ◫ 终端」。

所以需要一次连接——但只需要传目录，不需要传每一次按键。

## 形状

```
① 手机想控制 → 信标里发 cmd=3（请求目录）      认证、防重放，已有
② Mac 看到 → 作为 central 连上手机的 GATT      和配对同一个形状
③ Mac 写入目录（用 K_s 加密）                  一次，几百字节
④ 断开
⑤ 手机显示按钮；点一下 → 信标里发 cmd=16+i     每次按键，一个字节
```

**②③ 沿用配对已有的结构**：手机当 peripheral（`PairingServer.kt` 的写法），
Mac 当 central（`pair-with-phone.swift` 的写法）。两边都已经有能跑的代码可以照着写。

会话密钥：

```
K_s = HKDF(K, salt = 会话随机数, info = "repose-console-v1")
```

会话随机数由 Mac 在 ② 里给出，**每次重新协商**——目录不是秘密，但它泄露你在用哪些
App 和哪些快捷键，没有理由让它以明文在空中反复出现。

## 为什么不把每次按键也走 GATT

原计划是「Mac 连上手机，开一条会话，按键走会话」。改成按键走信标，理由：

- 信标那条路**已经通过实测**，会话那条还没有
- 每次按键都要建连接意味着延迟从「几秒」变成「连接协商 + 几秒」
- 手机上常开一个可连接的 GATT 服务，是这个产品目前唯一不存在的一类攻击面；
  只在传目录的那几秒开着，代价小得多

**代价**：一个字节只能表达「按第 i 个」，没有参数、没有返回值。手机点下去之后，
它知道自己发出去了，不知道 Mac 按没按成。这正是今天「锁定 Mac」的处境。

**要诚实地显示这一点**：按钮的反馈只能是「已发出」，不能是「已按下」。
（`ui-conventions` 1.1 —— 手机主屏那句「已发出」就是为这个写的。）

要真正的回执，得让 Mac 在状态信标里回一个「最近执行到 seq=N」。那是 macstate-v3，
不在这一轮。

## 手机侧

`ControlScreen.kt`：App 切换条 + 按钮网格，从电脑卡片的「控制」进入。
四种情形按 hi-fi 稿：可用 / 不在附近 / Mac 上关着 / 缺辅助功能权限
——**后两种按钮仍然在，点下去说去哪儿开**，而不是消失。

**手机上没有编辑器**：在手机上配电脑快捷键，是把最难的输入放在最小的屏幕上。
目录只能读，改要去 Mac。

## 还需要先决定的

1. **cmd 取值怎么分配**。16+i 的 i 是目录里的序号，那么改一次配置，序号就变了——
   手机上还没刷新目录时按下去，会按到别的操作上。**这是会真的按错键的路径。**
   倾向：目录带一个 revision（`work-console-v1.json` 里已经有 `revision` 字段），
   cmd 的高位带上 revision 的低 2 位，对不上就拒绝执行并让手机重新取目录。
2. **谁触发 ③**。Mac 要一直在扫 cmd=3，还是只在快捷控制页打开时？
   一直扫更好用，但也意味着 Mac 会因为一个信标就主动去连手机。
3. **每部手机的「允许控制」开关存哪**。计划里说在手机控制页，每部手机一个。
   那需要先有 P3 的「每部手机一个 keyId」，否则一台 Mac 上分不出是哪部手机在发。
   **这条把 P4 的开关挂在了 P3 上。**

## 已经能做、不依赖上面任何一条的

Mac 侧的操作编辑器。现在 `work-console-v1.json` 只能手改，而
「能按的操作」那一页是只读的。加编辑器不碰协议、不碰密钥、在一台机器上就能验完。
