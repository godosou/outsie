## 顺序

**B → C → A → D → E。** B 是 A2 和 C 的前提；C 删掉的页面 A 顺手收尾；D 是 A–C
之后的一次文案扫除；E 单独一节，因为它碰协议、碰无线电，而且量错了会连累解锁。
E 在 A–D 上真机看过之后再动。

## 每一步的做法

1. 先写测试，能在 JVM 上跑的都在 JVM 上跑（`gradlew testGenuineDebugUnitTest`、
   `npm test`、`cargo test --lib`）。SharedPreferences 不进单元测试，把槽键和整理逻辑
   留成纯函数。
2. 改完装真机，截图对照文档那一章的帧。
3. 一步一个 commit，commit 说明引用文档章节。

## 收口 workflow 的结果（2026-09-12 下午）

36 个 agent，无失败。Phase A 八个编辑器各自自检通过；Phase B 八个符号全部被判「没人用」，
一次串行删除后编译通过；文案复核零违规；行为复核六条里两条被反证方驳回，理由都成立，
已在主会话补上：

- `postCommand` 拒绝入队之后，主屏和控制页的吐司仍先问「是否入队」，钥匙关着会说成
  「还没有配对」；而且关钥匙不会重画卡片，锁定/控制仍可点。修：两处先问 `canSend`；主屏
  在「听到的 Mac 集合」变化时重画。
- 「量成功过」只在校准屏亲眼看到 CAL_OK 时记下，屏幕一重建就丢。修：在扫描器里收到签过名的
  CAL_OK 就记；流程状态挪到屏幕之外，重建不丢。
- 配对弹窗那句「这里会一直找」不实（Mac 三分钟就放弃）。改成「手机上要开着蓝牙，并且打开
  Outsie。三分钟找不到会停下来，重新开始就好。」

汇总 agent 发现 cargo 一条红：文案流把「密码照常可用」改成「能用」，测试没跟。统一成文档的
「密码照常能登录」，七处字符串和三条断言一起改。五个套件全绿后按流提交：
`4ebc1f6` 向量 · `7dfa0ed` 死代码 · `a3949d8` 文案 · `aac79e7` 行为 · `968ff5a` 签名 · `b10389e` 文档。

**接下来是 S2（要人）**：装签名版 Mac 包，`tccutil reset Bluetooth ai.repose.lite`，重新允许一次；

## S2 真机（2026-09-12 14:00–14:30，用户拿着手机走）

装了签名版 Mac 包，重新允许蓝牙一次；手机装新包。结果和修法：

- **卡片不亮。** 手机持钥匙位 15、166、17，只有 17 有记录；真 Mac（1FD4）在 166 下广播，验签通过
  （logcat `mac 1FD4 says UNLOCKED (key 166)`），但卡片按记录里的 macId 匹配，没记录的槽位永远灰，
  `noteMacId` 遇到没记录的槽位直接返回。修：sighting 带钥匙位，卡片和量距离屏先按钥匙位找；
  没记录的槽位第一次验签就建记录。
- **Mac 删掉手机之后。** ①「配对手机」藏在收起的「更多」里，列表空了看不到入口——按设计
  移到「你的手机」标题旁，常显。②删了钥匙文件，验证器缓存不失效，state.log 继续
  `key=166` 广播了 8 分钟（直到重新配对重启流水线）——验证器改成每秒确认钥匙文件还在。
  ③`revoke` 留下 `presence-key.N.phone` 和 `pairing/console-key.N`——一起删。
  ④用户说「列表没更新，要退出后才更新」：**没复现**（复现要在管理员密码框里打字，终端没有辅助功能权限）。
  代码路径读了三遍找不到原因，装新版再看一次。
- **手机移走之后。** 服务继续用删掉的钥匙广播（logcat `advertising started for keyId=17`，
  `key_ids` 已空）。修：`BleSpikeService.keysChanged`——还有钥匙就重建信标，没有就停服务。
- **锁定/解锁通了。** 重新配对到钥匙位 72，`bridge.log` ENTER/LEAVE、cmd 1 锁屏都对。
- **控制没通。** `verified.csv` 里今天只有 cmd 0/1/3/4；序号 63→64→65 连续，说明手机**没有发出任何
  快捷键字节**（不是 Mac 没听到）。手机已拿走，无法看 logcat；下次先看控制页有没有按钮（钥匙位 72 的列表
  是否收到、验签是否通过）。Mac 上辅助功能权限也还没给，通了之后还要那一步。
- **量距离卡在远处。** 近处量完（state 3），用户走到远处按「到了」，60 秒没反应。原因是设计：「到了」是
  蓝牙指令，远处出了范围 Mac 永远收不到。用户拍板：远处完全收不到也算数，并改成 20 秒倒数动画。
  已做（见设计文档第 05 章「远处听不见也是答案」「倒数，不计时」、第 14 章 cmd 6）：两段各 20 秒；
  近处不够样本才是「没听到手机」；远处样本不够 = 远处听不见 = 量好了（far = near − 12，记
  `farSilent`）；手机远处倒数完没结果进「走回去就完成」，每 20 秒补发 cmd 6，Mac 在 WAIT/FAR 收到就定下来。
  顺手修了一个旧 bug：`CalibrationOutcome` 的字段序列化成 `near_dbm`，前端读 `nearDbm`，Mac 侧弹窗
  一直把量好的结果读成 0。
- **Mac 侧「量一下距离」入口**仍保留（S3 条件「手机流程真机验过」还没满足）。

五个套件全绿（cargo 144 · npm 130 · tsc · gradle 68 · verifier 自检）。**下一次真机**：装新 Mac 包和新
APK；走一遍量距离（远处站到听不见的地方）；控制页看按钮和吐司；Mac 上删一把钥匙看列表是否即时更新。
- **装新包时又抓到一个**：App 重启后指令监视器的起点只看最新的快捷键行，今天没有快捷键、只有一次量距离，
  于是把 14:20 那条 cmd=4 当成新的重放了一遍，Mac 对着空椅子量了 20 秒，写了「没听到手机」。
  已修（起点取三类指令里最新的一条）并有测试。
- **验证器丢弃已删钥匙，本机实测**：临时目录放一把 root:wheel 0600 的钥匙，用同一条签好名的信标喂本机的
  `presence-verify`：删文件前 `auth=VALID`，删后 1.5 秒 `auth=NOKEY`，日志 `keyId 9: key file gone, no longer accepted`。
- **「删掉这把钥匙」的界面路径在浏览器里用假桥验过**：两部手机，删一部，列表当场少一行；再删一部，空列表，
  「配一部新手机 ›」只在标题旁一处。所以「要退出才更新」不在 React 这一层——如果新版还复现，就是 Tauri
  那边（例如某个前一次请求没返回，把后面的点击都吞了）。

## 用户回来之后的第二轮（2026-09-12 15:46–16:10）

- 手机新包自动装上；打开 Outsie 后卡片亮了，同步、锁定、量近处都到了 Mac。
