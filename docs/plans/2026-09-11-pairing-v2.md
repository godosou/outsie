# `repose-pair-v2` — 不用 QR 的 SAS 配对

日期：2026-09-11 · 取代 [2026-09-10 设计](2026-09-10-authenticated-presence-design.md) §1 的引导层
(在场信标层 `repose-presence-v1` 不变,已经在真机上验收过)

## 为什么不照搬 §1

§1 那套用 QR:Mac 屏幕显示二维码 → 手机摄像头扫 → 拿到一条"可信的 Mac→手机"单向通道,
再用 SAS 补上反方向。

**但在这个场景里,两块屏幕本来就在同一个人眼前。** 那么 QR 买到的东西,
一个 6 位数字的双向比对已经买到了 —— 而代价少得多:不需要在 Mac 上画二维码、
不需要在手机上要摄像头权限、不需要处理扫描失败。

这不是发明新构造。**这就是蓝牙自己的 Numeric Comparison,也是 ZRTP 的 SAS**,
公开发表、被广泛分析过。

## 协议

标签(精确 ASCII,任何一端改了都必须同步改另一端):

```
COMMIT = "repose-pair-v2 commit"
SAS    = "repose-pair-v2 sas"
KDF    = "repose-pair-v2 presence-key"
```

双方各生成一对**临时** P-256 密钥(用完即弃)。`Nm` / `Np` 是 16 字节 CSPRNG。

| # | 方向 | 内容 |
|---|---|---|
| M1 | Mac → 手机 | `PK_M` (65, SEC1 未压缩) |
| P1 | 手机 → Mac | `PK_P` (65) ‖ `Cp` (32) |
| M2 | Mac → 手机 | `Nm` (16) |
| P2 | 手机 → Mac | `Np` (16) —— Mac 在此校验 `Cp` |

```
Cp = SHA256(COMMIT ‖ PK_M ‖ PK_P ‖ Np)
```

**承诺先行是整个协议的支点。** 手机在看到 `Nm` 之前就锁死了自己的 `Np`,
所以中间人无法"先看对方的 nonce,再挑一个能让两边数字凑成一样的自己的 nonce"。
`Cp` 里包含 `PK_M`,所以一次承诺也不能拿去对另一台 Mac 重放。

```
transcript = SAS ‖ PK_M ‖ PK_P ‖ Nm ‖ Np
sas_hash   = SHA256(transcript)
digits     = int_be(sas_hash[0..4]) mod 1_000_000     // 6 位,左补零
```

人比对这 6 位。**不一致就中止,而且这对临时密钥作废**,不能重试 ——
否则中间人可以反复试到撞上为止(每次 10⁻⁶,重试无限次就不是 10⁻⁶ 了)。

两边都确认后:

```
Z   = ECDH_x(自己的私钥, 对方公钥)      // 32 字节,前导零保留
PRK = HKDF-Extract(salt = sas_hash, ikm = Z)
K   = HKDF-Expand(PRK, info = KDF, 32)
```

**把 transcript 哈希当作 HKDF 的 salt**,意味着即使 SAS 真的撞上了(10⁻⁶),
中间人两侧握着的也是不同的 `K` —— 他没法把两条链路接起来。

## 传输

一次性、当面、可以建连接 —— **不受"在场判定不能建连"那条约束**,
那条只管稳态信标。

手机在配对窗口内开一个 GATT 服务端(平时不开,信标是不可连接的),
Mac 作为中心连上去跑 M1/P1/M2/P2。窗口 **3 分钟**,过期则临时密钥、
nonce、SAS 全部作废。

## 这解决了什么,没解决什么

**解决:** 陌生人在配对过程中插一脚,把自己的密钥换进来 —— 两块屏幕会显示不同的数字。

**没解决:**
- 有人**拿到你的手机和 Mac** 亲自走一遍配对。物理占有从来不在威胁模型里。
- 在场层的重放与实时中继 —— 那是 `repose-presence-v1` 的已知残留,配对改不了它。

## 实施顺序(每一步都要能被上一步挡住)

1. **先把数学钉死。** 双方各自与独立生成的向量对答案 —— 不是互相对答案。
   两边都对着自己算的结果点头,是这个项目已经犯过的错。
2. Swift / Kotlin 各自 `--self-test` 通过。
3. 离线跑一遍完整交换(同机两个进程),验证 SAS 相同、K 相同。
4. **再上 BLE。**
5. 最后才接界面。

## 和 USB 下发的关系

`provision-dev-key.sh` 不删。它仍然是开发时最快的一条路,而且它的诚实标注
(「拿着线的人就是机主」)现在依然准确。配对做完之后,它变成
"开发用旁路",而不是"唯一的路"。
