# 单日活动图表设计

## 背景

「我的记录」目前只有最近七天的休息总量柱状图，无法回答“今天哪个时段专注、哪个时段休息”这一类问题。用户确认新增单日图表，以一天内的小时分布展示真实节奏。

## 用户故事

作为 Repose 用户，我希望按日期查看一天内每个小时的专注与休息分钟数，从而理解自己的工作与休息节奏，而不是只看到当天总量。

## 交互设计

- 「我的记录」默认展示今天，可通过左右按钮查看本地保留期内的前后日期，未来日期不可选。
- 图表横轴为 0–23 点。为了保证桌面与窄屏可读性，主刻度显示偶数小时，所有小时仍然保留可点击柱。
- 每个小时使用一根堆叠柱：绿色表示专注，暖橙色表示休息。
- 点击某个小时后，在图表下方显示该小时的专注分钟、休息分钟和合计分钟；默认选中当前小时，查看历史日期时默认选中活动量最大的小时。
- 当选中日期没有分时记录时，图表显示空状态；当天总量卡和休息足迹仍然正常显示。
- 当查看历史日期时，顶部摘要和休息足迹同步切换到所选日期。
- 图表按钮和日期切换按钮提供可访问名称、键盘焦点以及 `aria-pressed` 状态。

## 数据设计

计时状态升级为版本 3，新增：

```ts
interface HourlyStats {
  focusSeconds: number[] // 固定 24 项
  breakSeconds: number[] // 固定 24 项
}

hourly: Record<string, HourlyStats>
```

键名继续使用本地日期 `YYYY-MM-DD`。每次记录可信时间时，同时写入现有每日总量和对应小时桶。跨小时、跨午夜以及休眠/锁屏形成的休息区间都按本地时间边界拆分。重复的夏令时小时合并到同一小时桶，缺失小时保持为零。

版本 1/2 数据迁移到版本 3 时保留每日总量和历史记录，分时桶为空。因为旧数据没有足够信息，还原或猜测小时分布会产生错误记录，因此不回填。

分时数据与每日总量使用同样的 35 天保留窗口。本地存储恢复时逐项校验日期、数组长度及非负有限数值；异常字段归零或丢弃。

## 实现边界

- 使用 React 和 CSS 绘制，不新增第三方图表库。
- 本次只展示专注与休息两类汇总，不记录应用、键盘内容或窗口信息。
- CSV 导出继续导出每日汇总，本次不改变导出格式。
- 不提供周/月切换、缩放、云同步或单次专注会话列表。

## 测试策略

- 单元测试覆盖空白 24 小时、跨小时、跨午夜、休眠/锁屏休息、旧版本迁移、异常数据恢复和保留期裁剪。
- 前端构建验证 TypeScript 与生产资源生成。
- 使用正式 `.app` 验证图表页面、日期切换、小时选择、深浅主题和窄屏布局。
