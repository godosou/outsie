# 从界面卸载:还原干净了,但有三样没删,其中一样界面说删了

日期：2026-09-11 · 日常 Mac · 全程由使用者点击界面完成

## 还原对的部分

| 项 | 结果 |
|---|---|
| 锁屏规则 | ✅ 完全还原成 `["com.openai.sky…","use-login-window-ui"]` |
| **Codex 那个第三方插件** | ✅ **没被动** —— 我们只还原自己改的那部分,承诺兑现了 |
| 子规则 `ai.repose.spike` | ✅ 已删 |
| `ReposeSpike.bundle` | ✅ 已删 |
| 健康检查守护 plist | ✅ 已删 |
| `/Library/Application Support/ReposeSpike` | ✅ 已删 |

**最危险的那一种残留没有发生**:规则里没有留下指向已删组件的悬挂引用。
那种状态会让这台 Mac 对任何人敞开。

## 没删的三样

### 1. 配对密钥还在 —— 而界面说它被删了

移除确认框写着「删除这台 Mac 上的配对密钥」。

`uninstall.sh` **从来没碰过它**。它删 permit 文件,但 `/var/db/repose-unlock/presence-key.1`
原封不动。

更糟的是 App 的移除报告:

```rust
backup_used: true,
bundle_removed: true,
keys_removed: true,     // ← 字面量。从来没有观察过任何东西
```

**这是同一个模式的第六次**:界面声称了一件代码没做的事。而这次留下的是
**一把共享密钥,在用户明确要求"移除全部"之后**。

修法是两条:`uninstall.sh` 真的删,并且报告改成**从磁盘读出来的**——
新增 `uninstall_report(facts)`,把规则、组件、密钥、permit 目录、支持目录
逐项读一遍,残留全部列出来(一次列全,不是一次说一个)。

### 2. `/var/run/repose-spike` 目录还在

删了里面的 permit 文件,没删目录。

### 3. 在场监测管线还在跑 —— 而且跑了两个

卸载没有停它。于是扫描器继续扫、继续往一台**已经没有插件**的机器写 permit,
面板还会报告"监测运行中"。

卸载现在会先停监测再拆东西。

## 顺带:孤儿扫描进程

清理时发现**三个 `rssi-scan` 还活着**,父进程早没了。管线的退出处理会回收它,
但退出处理不运行的时候(强杀、崩溃、App 被强制退出)就会留下一个
**占着蓝牙、耗着电、为没人用的功能扫描**的进程。累积到三个才被看见,
而界面上永远不会提这件事。

扫描器现在自己看 `getppid()`,父进程没了就退出。

## 这台 Mac 现在的状态

全部清理干净:规则原样、无我们的插件、无 permit 目录、无密钥目录、无残留进程。
