# B2 —— 真手机 BLE 在场驱动解锁 permit：端到端跑通

日期：2026-09-09

状态：**核心已验证（CONFIRMED）**。真实手机 BLE 在场 → macOS 扫描 → 桥 → VM 上的加固 permit →
门控授权，双向都通。剩「锁屏唤醒」这一最终手势需要 GUI + 使用者在场。

## 拓扑

VM 无 BLE 射频，所以由**宿主机** Mac 扫手机，permit 经 ssh 送进 **VM**（插件所在）：

```
手机(广播)  ──BLE──▶  宿主机(rssi-scan | permit-bridge)  ──ssh sudo──▶  VM(/var/run/repose-spike/permit)  ──▶  VM 插件
```

证明的是「真实 BLE 信号 → 在场判定 → 加固 permit → 授权」整条软件链。测的「距离」是宿主↔手机、
解的是 VM 的锁 —— 人为但安全。真实产品拓扑（扫描器与插件同机）是另一个需显式同意的决定。

## 这次实跑（真机 9535e9c2，realme/ColorOS）

1. **手机侧**（经 adb 驱动，使用者已授权操作手机）：APK 已装、三项运行时权限 `granted=true`、蓝牙开；
   `am start` 把 `MainActivity` 调到前台，`uiautomator` 定位 **START ADVERTISING** 按钮
   （bounds `[0,140][1264,308]`），`input tap 632 224` 点击。
2. **宿主机侧**：`swiftc` 编译 `rssi-scan`；蓝牙对终端已授权（`STATE poweredOn / SCANNING`，无弹窗）。
   扫描 12s 即见手机广播：`READ MATCH: "repose-hello"`，RSSI −68…−80 dBm（两个外设 ID = RPA 地址轮换）。
3. **联动**：`rssi-scan --duration 30 | permit-bridge.sh`（近≥−78，远≤−88，静默 6s 判离开，每 3s 刷新），
   桥默认把 permit 经 ssh 写进 VM。

观测（用「广播开/停」代理「手机在/离开」，无需物理移动手机）：

| 手机 | 桥日志 | VM permit | `security authorize`（无凭据）|
|---|---|---|---|
| 广播中 | `ENTER (rssi=-74) -> asserting permit` | `-rw-r--r-- root wheel` | **YES (0)** |
| 点 STOP | `STALE (no sample for 6s) -> clearing permit` | 已清除 | **NO (-60007)** |

即：真手机靠近（广播）→ VM 出现 root 新鲜 permit、授权放行；手机离开（停播）→ 静默超时清除 permit、
授权退回要密码。与加固 permit 的「root 持续刷新、过期即拒」模型完全吻合。

## 阈值与延迟（诚实记录，均非出厂值）

- NEAR/FAR 用的 −78/−88 dBm 是**占位**，绑死在 spike 的 MEDIUM tx power；真实校准是 B3。
- B1 记录的发现延迟 p95 ≈ 5.4s（macOS 扫描窗口约每 1.5s 开一次，Android 广播上报仅 ~0.44/s），
  高于 3s 解锁预算；桥的在场判定对这个延迟是鲁棒的（在场是持续状态，不是单次命中），但**首次**解锁的
  端到端时延可能超预算，B4 需量化，必要时放宽预算或提高广播/扫描节奏。
- RPA 轮换使同一手机呈现多个外设 ID；桥不依赖 ID（只看任一匹配服务 UUID 的广播的 RSSI），不受影响。

## 还差的一步（需 GUI + 使用者）

完整演练：锁定 VM → 手机在场 → 唤醒 → 免密解锁；手机离开 → 唤醒 → 出密码框。唤醒手势用
`tools/vm-spike/vm-wake-submit.sh`（短暂占用宿主机焦点），只在使用者说宿主机空闲时做。
permit→解锁这半段此前的验收跑已证，故 B2 的**新增**部分（真实 BLE → permit）已完成。

## 复现

- 手机广播：`adb -s <dev> shell am start -n ai.repose.blespike/.MainActivity` → `input tap 632 224`（START）。
- 宿主：`tools/ble-spike/mac/rssi-scan`（先 `swiftc -O -o rssi-scan rssi-scan.swift -framework CoreBluetooth`）。
- 联动：`REPOSE_SSH='ssh …vm…' REPOSE_NEAR_DBM=-78 … rssi-scan | tools/ble-spike/mac/permit-bridge.sh`。
- 校验：VM 上 `ls -l /var/run/repose-spike/permit`、`security authorize system.login.screensaver`。
