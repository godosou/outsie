The latest phone-workspace iteration restores the existing prototype’s realistic device and application UI, with the phone on the left and the Mac screen on the right. Configuration forms, logs, connection toggles, layout editing, and the nine-button grid are omitted. Other feature demos remain concise.

`app/product-demos.tsx` renders the break, stretch and Phone Key previews. `app/phone-workspace-demo.tsx` adapts the original prototype’s UI and interaction model into the homepage. At desktop widths the phone is left and the Mac is right; narrow screens stack the phone before the Mac so controls remain readable. All interactive state is confined to this web page. No real devices, pairing, system control, speech recognition, or AI execution are involved. Phone action captions explicitly say the page is a simulation. The surrounding copy presents headset voice as agreed functionality, following the user’s explicit copy instruction; it does not add speech capture to this website.

`public/demos/stretch-focus.webp` was captured directly from the existing 3D preview on 2026-09-08. Only the browser capture layout was changed: the scene was presented at 720 × 640 CSS pixels on a plain background, with surrounding application chrome and overlay labels hidden. The model, pose, camera, and lighting were not retouched. The screenshot is 1440 × 1280 pixels (device scale 2), saved directly as WebP. Red shading is the app's illustrative stretch-region overlay, not a precise anatomy claim. The 3D human derives from CC0 MakeHuman core assets as documented in the parent app's `src/assets/STRETCH-HUMAN-LICENSE.md`.

The previous six full screenshots and their lightbox component were removed from the current website bundle. They remain in Git history. No generated product screenshots or new artwork were added.

The phone workspace remains a bounded simulation: splits use two panes, the sequence selects a second example window and splits it, and three example Codex tasks cycle locally. The review action prepares an unsent prompt draft, mirroring the original prototype’s template behavior. No new native functionality is claimed. The original branch is read-only; only homepage files are modified.

The separate static tmux/Codex/Feishu example tabs were removed as duplicate content. The App tabs inside the interactive phone and all demo actions remain.

The hero uses a compact phone/Codex input illustration as a link to the full workspace demo, alongside a working 20-second countdown. The input illustration is labeled as an example and has no recording or send controls. It reuses the existing product UI motifs and flower asset; no new artwork or screenshots are generated.

Phone Key now uses `app/phone-key-demo.tsx` and `app/phone-key-demo.css`. A ten-second sequence plays once when the scene comes into view, with pause/replay controls and work/break scenarios. Playback suspends outside the viewport and when the page is hidden. Reduced-motion settings disable automatic playback and visual transitions. The phone moves away from and back toward the Mac; the Mac locks, verifies the key, then restores the workspace or continues the simulated break. It does not connect to devices, authenticate a key, or lock the visitor’s computer. The old static two-row diagram and its styles are removed. The v0.6.2 download scope is unchanged.
